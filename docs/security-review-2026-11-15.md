# GUI 3.6.0 CONNECT security review

Scope: source review, dependency audit and local regression tests for the application, signed updater, privileged manager, Bluetooth receiver and USB measurement worker. This is not a penetration-test or hardware certification. No production credentials, signing key or Pi was accessed. OTA publication remains subject to owner approval.

## Changes

- **Origin/Host:** the app accepts its actual loopback/device hostname/interface addresses, plus explicitly configured `DAW_ALLOWED_HOSTS`. Arbitrary DNS names are rejected before API/static handling. Cross-site or mismatched-Origin API requests are rejected even when only reading the public control nonce. Caller-provided `X-Forwarded-Host` cannot satisfy a control check. Reverse proxies must explicitly configure their public host; forwarding a header alone grants no trust.
- **Music Assistant credentials:** a saved token is bound to the canonical server endpoint. Changing host, port or TLS scheme does not silently forward the old credential. Explicitly supplied replacement credentials are still supported. Switching to an anonymous server clears the previous token reference/file. Token files and legacy environment credentials are readable by the backend control group, not the capture/receiver accounts. Token files have explicit group-read-only permissions even under the manager's private umask; nothing is written to browser storage or returned in source summaries.
- **Privilege boundary:** the root control socket/runtime directory uses the separate `dawcontrol` group. Only the application user is added; USB capture and Bluetooth audio users retain audio access without manager-socket access. Root JSON writes use unpredictable exclusive temporary files, explicit modes and fsync, avoiding the predictable `.tmp` symlink primitive. Journals remain root-private; explicitly public runtime telemetry is 0640, not world-readable.
- **Browser:** the existing managed appliance policies suppress translation, password/autofill/sign-in, notifications/permissions, native file pickers, downloads, external windows and browser shortcuts. Web Bluetooth and browser microphone capture remain disabled. New upload instructions use a computer rather than opening a native chooser on the appliance. Production responses add nosniff, same-origin framing and a CSP limited to the app and the official, consented YouTube embed/SDK origins. The YouTube frame remains sandboxed and silent, with an owned ready/error state.
- **Bluetooth:** explicit local source ownership, authoritative ungrouped/paused checks, muted entry, independent amplifier attenuation, bounded pairing, numeric comparison, audio-only service authorization and journalled restore. Old source-session volume events cannot act on a new source. No always-open discovery or automatic acceptance of unknown devices. An appliance-owned approval list and explicit BlueALSA MAC filter exclude old OS-trusted devices; the broad BlueZ Trusted flag is not granted to newly approved phones. An empty or wildcard peer list cannot start audio. Selected Bluetooth audio blocks OTA and sweeps.
- **Measurement:** USB-only capture, explicit audible consent and verified output remain required. The worker waits for actual samples before playing, rejects incomplete/unrelated sweeps as well as noise/clipping, imports bounded calibration data, restores a journalled flat baseline and separates verification of current DSP. Legacy/verification captures cannot be applied as a new correction. Cancellation and systemd post-stop remove raw recordings. Only processed response data remains.
- **OTA:** Ed25519 verification, pinned project key, immutable inventory/hash checks, unprivileged `npm ci --ignore-scripts`, anti-replay sequence, idle checks and health rollback are retained. Tar inventory bounds now reject an oversized member header before advancing through its compressed payload. Optional audio package installation is not added to automatic application OTA. Checkout and setup-node actions are pinned to their verified upstream v4 commit SHAs; the publisher does not persist checkout credentials.

## Audit result and limits

The npm audit on 15 November 2026 reported **zero known advisories**, including development dependencies. Lockfile/dependency versions were not changed by this candidate. This does not establish freedom from unknown vulnerabilities or flaws in OS/BlueZ/kernel packages. Installer/package updates remain a separate host responsibility.

Local checks cover forged origins/forwarded hosts, DNS-rebinding hostnames, credential endpoint scoping, private umask behavior, temporary symlinks, socket command schemas, PIN/nonce rules, raw audio cleanup paths, sweep quality, Bluetooth level/restoration and update idle gates. Browser/physical acceptance results are recorded in [CONNECT validation](connect-validation.md).

Public playback actions intentionally remain usable while the settings PIN is locked. The PIN protects settings, source pairing and device changes, not household playback authorization. The backend binds to loopback by default; remote management should use the existing SSH tunnel or narrowly configured local provisioning path. Do not expose the device HTTP port directly to the Internet.

Outstanding physical/service acceptance: real phone/BlueZ/Louder behavior, calibrated USB microphone repeatability, live Google/MA provider permissions, sync/decoder timing, GPIO wake and the unresolved supply interruption. Manual screen timing remains an estimate; sweep capture delay is not used as automatic Squeezelite visualizer compensation.
